
## Findings and recommendation (author's reading of the tables above)

1. **arris 0.11.1 is the best fit for GEO-1 today** among kernels that can sit in a Rust, permissive-licence, memory-safe product: it builds every form except the cornered sweep (mitre refused; fuse of two boxes works), every shared-face boolean is valid, hostile input returns errors (no panic, no crash, no silent acceptance), it has a chord-controlled tessellator (736 / 2212 tris per panel at 2 / 0.5 mm), all 8 crates forbid unsafe, 46 crates in the tree, all MIT/Apache, 55 s clean build. Costs: a boolean void is the slow path (about 44 ms/panel/core, 15 s for 10,000 panels on 72 shared cores, over budget on 1 and 8 threads) while the same void as a profile hole is about 25x cheaper (0.8 s on 72 cores, 4.2 s on 8) - keep the profile-hole fast path of PR #81; free-form booleans cost seconds each; fillet on NURBS-NURBS hangs (case 6c of the NURBS table timed out at 90 s, as in the earlier run).
2. **solidcore 1.0.1 is the strongest on geometry but cannot mesh**: forms, shared-face booleans, free-form booleans (17-52 ms for the NURBS cases that fail or take seconds elsewhere), a mitred planar-path sweep and fillets all work and pass its integrity check, 13 crates, Apache-2.0, `forbid(unsafe_code)`. Blocking gaps: no surface tessellator (README: "not ported yet"; only edge polylines), no STEP writer, degenerate input is accepted silently (zero-length extrude and a self-crossing profile both return a "valid" solid), and 10,000 panels cost 7-13 s on 72 cores and 5 GB. Worth a second look once it tessellates; a Rust tessellator on top of its exact B-rep is the missing piece.
3. **OCCT (opencascade-rs) is the feature-complete reference, not a fit as the product kernel**: everything builds, booleans on shared faces are fast (2-6 ms), smooth lofts and blends work, STEP works; but LGPL-2.1 C++ (vendored, 3 non-permissive licences flagged), a NaN input segfaults the process (exit 139; needs process isolation), a mitred sweep returned a result that cannot be meshed, and it scales badly with threads (10,000 panels: 13.9 s on 8 threads, 26.7 s on 72). Useful as an oracle for validating arris/solidcore results, or as an out-of-process fallback.
4. **truck is not ready for these cases**: four shared-face / flush booleans return `None`, boolean void at 10,000 panels times out at 90 s on every thread count, no fillet, no smooth loft, no path sweep, panics unguarded in shapeops are possible (none seen). Its strength is that building without booleans is almost free (panels with the profile hole: 0.12 s on 8 threads).
5. **Fornjot fj-core 0.49 cannot build most of the suite** (no revolve, no sweep path, no loft, no boolean, no NURBS), it panics on all three hostile inputs (validation panics on drop), and costs 4.8 MB per `Core`, 48 GB for 10,000 panels. Out.
6. **BIMCraft's mesh path stays an order of magnitude or two faster** (10,000 panels: 0.04 s no void, 0.12 s with a mesh-CSG void on 72 cores) at a fixed tessellation, with no curved surfaces; a B-rep kernel is justified for exactness (curved panels, STEP, 0.5 mm chord) not for speed. Suggested split: keep the mesh path for bulk display, arris for exact geometry, with voids as profile holes wherever the through-void is a circle.

Honest limits of this run: the machine was shared (load 45-65), so treat 72-thread columns and build times as noisy; NURBS-table rows marked `not run` were not implemented for solidcore/truck/OCCT in this pass; Fornjot's panel is slab-only; OCCT's loft is always smooth; the BIMCraft panel differs slightly from the kernel panel.
