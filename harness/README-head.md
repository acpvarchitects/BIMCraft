# B-rep kernel benchmark for GEO-1 (ADE run)

Scratch benchmark, 2026-11-17. Orphan bench-only branch; nothing here is product code. Raw logs: `logs/<kernel>/`, raw records: `results/<kernel>.jsonl`, licence/crate data: `results/<kernel>.licenses.json`, harness: `harness/`. This README is generated by `harness/report.py`.

## Machine and caveats

- ADE: 72 logical cores (Intel Xeon w9-3475X), 503 GB RAM, Linux 6.8, rustc/cargo 1.100 stable. The earlier reference numbers came from an 8-thread laptop.
- **The machine is shared.** Load average was 45-65 on the 72 cores for the whole run (other users' builds and services), so absolute times, especially 72-thread columns and build times, are noisy and pessimistic. Read ratios, not decimals.
- Every call ran in a child process: 90 s budget, 96 GB address-space cap (`RLIMIT_AS`), `/usr/bin/time -v` for peak RSS. A killed call is recorded as TIMEOUT (its RSS is the peak at the kill); a crash as CRASH(exit code). No call hit the memory cap.
- Dependencies were built only as cargo dependencies; nothing from their source dirs was executed. OCCT needed cmake, which the machine lacked; I installed it without sudo in a python venv (`pip install cmake`, 4.4.5, with `CMAKE_POLICY_VERSION_MINIMUM=3.5`) and built OCCT 7.8.1 from the vendored `occt-sys` source. Each kernel's target dir was deleted after recording (peak 1.5 GB for OCCT, 0.2-0.4 GB for the Rust kernels).
- `truck` here is the ricosjp crates (modeling 0.6.0, shapeops 0.4.0, meshalgo 0.4.0). The earlier `mt-t` probe used `monstertruck` (a fork); its results (`mt-results.md`) are kept for reference but were not re-run.

## Method

- Suite: the branch's existing code (`arris-t`, `arris-perf`) ported 1:1 to each kernel API: six forms (extrusion, blend, revolve, sweep with a mitred/cornered path, swept blend, void), shared-face booleans, box - cylinder, ring - box, hostile input (NaN, zero length, self-crossing), the NURBS table, and 10,000 different panels.
- Where a kernel has no equivalent operation the row says `CAN'T BUILD` with the reason. Rows marked `not run` are NURBS-table items I did not implement for that kernel in this pass (time-boxed), not claims that it cannot do them.
- Panel (`params(i)`, all values differ per panel): L slab (width 1200-1570, 6 plan vertices) extruded 50-60; ring revolved about Z (r 40-84 .. 80-88, h 150-166); ruled loft square (300-318) to circle (r 60-82) 400 high; one round through-void (r 30-44). Variant `b`: void by boolean cut of a cylinder; variant `c`: void as a hole in the slab profile (no boolean). BIMCraft's own `geo_bench` panel (PR #81 branch `vp/geo2ef-void-fast-paths`, run unchanged with `GEO_PANELS`, `RAYON_NUM_THREADS`) differs slightly (knob revolve, loft with a top hole) so its row is comparable in kind, not value-for-value.
- Meshing: chord 2 mm and 0.5 mm via each kernel's tessellator, panels counted as triangles per panel (all three bodies of the panel).
- Threads: rayon pool of 1, 8 and 72 (`RAYON_NUM_THREADS` / explicit pool). "n=1000" runs are given because several 10,000 calls exceed the 90 s budget.
- Fornjot panel = slab only (no revolve, no loft), variant `b` uses its through-hole operation (it has no boolean). Fornjot keeps one `Core` per panel (my harness holds them for meshing); each `Core` costs about 4.8 MB, hence the 48 GB RSS at 10,000 panels.
- OCCT: the loft wrapper (`Solid::loft`) always builds a smooth ThruSections loft (ruled is not exposed), so its "ruled" loft is smooth; the panel harness uses `unsafe impl Send/Sync` on the shape wrapper to run in rayon (own harness code, not the crate).
